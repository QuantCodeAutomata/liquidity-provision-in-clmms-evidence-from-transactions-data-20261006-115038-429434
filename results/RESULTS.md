## Deviations from the paper

1. **Synthetic data instead of real on-chain data.** The paper uses transaction-level event data from The Graph or a similar indexer for four Base-network WETH/USDC pools over September 2024 – July 2025. This implementation fetches live data via The Graph when credentials are present (`THEGRAPH_BASE_URL`, `THEGRAPH_API_KEY`) but falls back to the synthetic generator (`src/generator.py`) when those variables are absent. All headline metrics in this run are therefore derived from synthetic data; real-data results are expected only when the environment provides valid credentials.

2. **Retention rate at dynamic-balance stage (Exp 1).** The paper reports approximately 65 % retention after the dynamic-balance filter (Section 2.1, p. 4). In this run, 100 % of events are retained because the synthetic generator produces only fully reconstructable events (no pre-window liquidity). The filter itself is correctly implemented in `src/pnl_reconstruction.py`.

3. **Profitability rate (Exp 2).** The paper reports approximately 15.7 % of LPs have positive terminal PnL (≈ 1 in 6; Section 4.2). This run yields 45.9 %, because the synthetic generator assigns random PnL signs roughly uniformly, not replicating the real-data adverse environment for LPs.

4. **Multi-LP share (Exp 3).** The paper reports approximately 10 % of unique LPs operate across multiple pools (Section 4.2, Table 5). This run yields 1.8 % because the synthetic LP address space is generated independently per pool with minimal designed overlap.

5. **Types 5+6 combined share (Exp 4).** The paper reports > 90 % of transactions and capital in Types 5+6. This run yields 74 % because the synthetic data does not replicate the strong empirical concentration of activity around the current pool price.

6. **Type 5 Δ (price traversal fraction).** The paper reports ≈ 8 % weighted Δ for Type 5 consistent-success positions (Section 4.3). This run yields 4.3 %, a smaller traversal fraction, because the synthetic price paths are shorter and less volatile than the 11-month real-data price trajectories.

7. **Burn–collect matching algorithm.** The paper describes the burn+ pairing conceptually (Section 2.1) but does not give an explicit matching key or tie-breaking rule. This implementation pairs each burn event with the temporally nearest unmatched collect event from the same LP and pool, sorted by (block_number, tx_index, log_index). This choice is documented in `src/pnl_reconstruction.py` and is treated as assumed, not paper-confirmed.

8. **LP identity across pools.** The paper does not specify whether LP identity is the EOA address, NFT owner, or recipient field. This implementation uses the `owner` field across all four protocols, which are all Uniswap-V3-compatible. The choice is treated as assumed.

9. **Capital-weighted closing price.** The paper refers to a "capital-weighted closing price" P_end but does not provide an explicit formula. This implementation computes P_end = Σ(burn_capital_s) / Σ(burn_amount_s × P_js) evaluated over contributing burn+ events, equivalent to the weighted average of per-burn prices weighted by their realized capital contribution.

10. **Authors' data and code.** Reference [20] cites a GitHub repository for source code and data. The repository URL is not included in the paper text; a direct access attempt was made but the URL could not be resolved from the available reference. Any details it might resolve about burn–collect matching or exact field names have been treated as assumed where they differ from the above.

## Not Reproduced

1. **Real on-chain data results.** The paper's headline results (Tables 1–7, Appendix B) are based on real transaction-level data from The Graph for Base-network WETH/USDC pools. Without valid `THEGRAPH_BASE_URL` / `THEGRAPH_API_KEY` credentials in the execution environment, the live data path cannot be exercised. The data loader (`src/data_loader.py`) implements the full GraphQL query logic; providing credentials will switch the pipeline to real data automatically.

2. **Figure 4 (UpSet / Venn cross-pool participation diagram).** The paper's Figure 4 is a visual cross-pool participation diagram. This implementation outputs `results/exp3_cross_pool_participation.png` with a bar-chart equivalent; an UpSet-style plot is available via the `upsetplot` library but was not installed in the base environment.

3. **Tables 8–10 at full paper scale.** The paper's Appendix B tables cover all five width buckets for every win-position type at full real-data scale. The equivalent tables in this run are produced but are underpopulated due to the small synthetic universe; the column definitions and computations are correct.

4. **Position types 13–15.** Types 13–15 (PnL-neutral positions) require the opening and closing capital to be equal within a numerical tolerance. The synthetic generator does not produce this boundary condition by design; no positions of these types appear in the run. The classification rule for types 13–15 is implemented in `src/position_types.py`.
